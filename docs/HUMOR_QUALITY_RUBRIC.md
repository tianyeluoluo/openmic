# 中文单口质量校准：R1 反馈与公开资料

本页记录文本生成 v1 首轮评分后的质量校准。十条旧轨迹、R1 原始评分与自动结果保持不变；后续新协议使用独立目录，不能拿旧分数冒充优化后的效果。

**当前协议说明（v27）**：下文按历史过程记录，早期固定组数、双回调和固定数量 JSON 修稿已不代表当前要求。现在以整件事的笑感与事实连续性审稿，时长只作上限；结构标注不决定笑点质量，回调可选。当前提示与实测局限见 [CFUNSET_CONTENT.md](CFUNSET_CONTENT.md) 和 [CFUNSET_RESULTS.md](CFUNSET_RESULTS.md)。

## R1 反馈如何解读

匿名条件表的十条脚本由同一位评分者 R1 给 1–5 分。五主题配对后，幽默均值 baseline 与 CFunSet 都是 2.8；文化适配分别是 2.6 与 2.8。每条件仅五条，评分者也只有一位。R1 对幽默和文化两项更有把握，因此先用它们定位问题；口语与结构分数保留，不人为调权。禁止用这十条脚本或分数训练后再用同一批样本声称效果提升。

| 主题 | 幽默差值（CFunSet - baseline） | 文化差值 |
| --- | ---: | ---: |
| 我的网购经历 | -1 | -1 |
| 食堂排队 | -1 | +1 |
| 赶早八 | +1 | 0 |
| 地铁通勤 | +1 | +1 |
| 手机电量焦虑 | 0 | 0 |

地铁主题两种条件的绝对分数都偏低；手机电量主题两种条件的幽默度都较高。这提示场景与主题本身的重要性，不能把差异都归因于是否检索 CFunSet。

逐稿检查发现三个可操作的问题：

1. 一些包袱只是重说铺垫、给普通经历换一个抽象比喻，或在揭底后解释笑点。较有力的段落往往有可见动作、精确数量、短对话与一个新的误解结果；这只是对 R1 样本的定性观察，不代表统计规律。
2. 部分 JokeWriter 输出混入“依据上游结论”“正常预期”等策划语言；某条返工后的脚本丢失全部结构标签，却仍被模型 QC 批准。
3. 少量 CFunSet 检索样例带有吸烟或成人情节，跟校园演出语境不合。检索层现在跳过这类参考：固定索引中 11,236 条训练示例里有 121 条被舞台适配规则排除；五主题的原三个示例中，食堂和地铁各替换一条。原始索引与首轮轨迹均未改写。

将新的确定性协议检查**离线**应用于十条旧脚本，6 条通过、4 条被标出（回调距离、早八地铁情境或结构标签问题）。这只说明新检查能发现若干旧问题，不能推断新生成会有 6/10 通过率，更不能推断幽默分会提高。

## 写作与质检的参考标准

每组铺垫先建立可相信的具体预期，再用新信息打破它。优先考虑语义双解、角色错位、因果反转或有明确边界的夸张；同一篇要有变化。结尾回调应改变锚点的含义，而非简单重复。模型 QC 对换词复述、泛泛比喻、解释笑点、策划语泄漏和文化情境不通顺必须降分并要求返工。程序另行硬性检查结构标签、相隔的双回调，以及“早八直接坐地铁却没有走读/跨校区解释”这一已观察到的场景错误。程序能验证**协议与少量显式情境**，不能验证观众会不会笑。策划语的识别交给模型，以免简单关键词造成大量重试与额外 API 花费。

这些反转机制参考 [Tseng 等人的中文幽默语料研究](https://aclanthology.org/2020.lrec-1.168/)：其分类包括双关、夸张、桥接推理和反讽等。该研究也发现，单人标注的 1–5 幽默等级与用户反馈的相关性有限。因此，不能把任何网上“高分”或获奖段子直接视为客观 5 分金标准。它研究的是短笑话，也不能直接代表三分钟校园单口的效果。

作者公开了[带人工标注的中文笑话仓库](https://github.com/SamTseng/Chinese_Humor_MultiLabeled)，但论文说明语料来自 41 个来源。仓库的 MIT 标识不等于逐条原作品的许可都已核实。网上获奖或热门表演可能有更强的表演价值，但当前没有逐条核实可复用授权与真实评分口径，故本项目没有抓取、复制或微调这些台词。需要复用某作品原文时，应先确认其授权条件；[Creative Commons 的重用说明](https://creativecommons.org/reusing-cc-licensed-content/)也要求按作品许可保留署名等信息。

## 下一次可信验证

- 在**新输出目录**运行改进后的提示与检索，记录代码提交、模型、温度与数据版本；当前 benchmark manifest 已加入生成协议版本，防止混用旧轨迹。
- 使用尚未参与本轮提示优化的新主题作留出集，最好也保留旧主题做可比的回归检查；不能用 R1 的旧分数直接给新稿打分。
- R1 可以继续独立评分；若暂时没有 R2，报告只称“单人评分”，按主题列出差异和失败案例，不做显著性或普适性断言。
- 若将来拿到明确授权的优秀表演文本，可建立有来源、许可、时间和多位评分者的参考库；优先提炼机制与节奏，避免在生成时照搬原句。

## 增量反馈与故障记录

第二轮只生成一对网购稿。R1 匿名评分显示 baseline 幽默 4、文化 3，CFunSet 幽默 3、文化 4；R1 还指出 CFunSet 稿“包邮”后却让买家上门取货。第三轮缩短了稿件，但发现一个空 `[CALLBACK]` 仍被规则计数。当前版本补充包邮与自提的情境常识，并只把后接实际可朗读文字的回调算作有效。上述改动是针对可复核错误的修复，**尚不能证明幽默度提高**。完整小样本数字见 [CFUNSET_RESULTS.md](CFUNSET_RESULTS.md)。

第四轮两篇稿虽然通过结构协议，质检文本都在 `APPROVED` 的同时指出具体待改处。现在路由器会把这类自相矛盾的批准送回 JokeWriter；若两次返工后仍有明确问题，则最终结果不标记为批准。该规则只识别有限的明确措辞，不能代替人工判断包袱是否好笑；第四轮原始轨迹和待评表不改写。

R1 后来完成第四轮评分：baseline 的幽默/文化/口语/结构为 2/3/4/3，CFunSet 为 2/2/3/3。评论指出两篇都缺强反转，且“包邮”被过度使用；增强稿中的取件收费和工作人员擅用顾客包裹也缺乏生活依据。于是下一版逐段采用“真实日常目标 → 小而可能发生的意外 → 人物为解决它采取行动 → 冲突升级及可见后果”的检查顺序。人物行为、交易流程和时间顺序要经得住普通观众追问；偶然性应推动冲突，而非直接替代因果。模型判断仍须由新稿人工盲评校准，不能把修改后的提示当成已证实提升。

v6 试稿又暴露跨段连续性：单段看似可信，连起来却出现没铺垫的新商品、新待办，或默认校园物流服务必然采用某种交接规则。后续检查不只问“这一段可能吗”，还逐段问“它是否接着上一段的物品、地点与目标自然发生”。v6 两篇已匿名保存待人工评分；模型质检分与结构代理分都不能替代这项观察。

现在另用 CFunSet 的 4,200 条短文本幽默二分类记录训练本地字符特征模型。固定留出测试集 ROC AUC 0.7522，但它学习的是社交短文本标签；v4 两篇人工幽默均为 2 分时，本地模型对其包袱组合仍给出 0.9054/0.7507 的均值概率。**不要把这个概率当成观众幽默评分**。自动优化中它只作次要筛选信号，真实流程错误、跨段连续性和结构协议优先；对已有评分稿调过审稿规则后，旧稿不能再用于宣称独立泛化效果。

独立审稿要求每个问题列组号、原文证据和修法；第二次审稿专查普通人是否会这样行动，以及物品、时间、地点和交易状态是否连续。初期整篇自由重写常丢结构标签或把原有矛盾扩大，因此修订改为固定数量的 JSON 铺垫/包袱和两次回调，由程序渲染及检查长度；若反复卡在一个机械故障上，可重规划完全不同的日常冲突。若所有候选仍未通过，应明示失败并交由人类评分或重新选题，不把模型自评高分当成成功。

食堂小试的两篇盲评稿实际是同一故事的局部修订，归一化相似度约 95%；因此不计作两篇独立样本，后续先运行 `check-pilot` 做同主题近重复拦截。R1 给已评的 Q01 幽默 1/5、生活真实感 2/5，并指出靠教学楼闸机收尾不符合普通上课场景。资料显示特殊预约空间可能刷卡，但不能把这种规则默认搬到白天普通教学楼。现有自动审稿曾漏掉这一错误，新版明确检查它，并要求偶然事件经人物应对形成真正戏剧冲突；单纯接连倒霉不能获得高幽默分。这个修补来自同一位评分者的错误案例，仍需不同情节的人类盲评验证。

在扩写前筛选核心情境可减少把普通事故拉长成三分钟稿的浪费：先看日常目标和偶然是否可信，再看人物的主动选择是否造成戏剧冲突，最后看揭底是否改变观众预期。当前“拿错伞”开发试验中，三轮不同配置的提案均未得到偶然性 4/5，流程没有扩写任何新稿。它暴露的生成偏差是堆同款道具、隐藏标签、第三人和多次巧合；阻止这些情境进入扩写是有效的流程控制，但没有人类新稿评分，仍不能把它称作幽默质量提升。
