# CFunSet 中文幽默生成与对照实验

## 范围与来源

本模块对应课程任务二。官方 [CFunSet 数据卡](https://huggingface.co/datasets/ZhenghanYU/CFunSet)说明数据是 `instruction`、`input`、`output` 三元组，约 164,200 条，混有幽默解释、分类、相声应答、笑话生成和续写；[论文](https://arxiv.org/abs/2503.20417)介绍了数据集及 CFunModel。代码固定数据仓库版本 `39ded465de072b19d4b843e319d7dc85d704be5f`，并验证官方 LFS SHA256。

数据卡未标出明确的整体许可证；其来源又包含多个子数据集。因此仓库**不提交原始语料、派生示例索引或完整批量生成轨迹**。课程汇报只展示筛选后的自主创作短节选和汇总指标，原例保留来源记录。公开复用、再分发或商业使用前，应向数据权利方核对许可。课程内部实验需保留来源与版本记录。

## 数据准备

在仓库根目录运行：

```bash
python -m pip install -e .
python -m openmic.humor_benchmark download
python -m openmic.humor_benchmark prepare \
  --source artifacts/cfunset/CFunSet.json \
  --index artifacts/cfunset/index.jsonl
python -m openmic.humor_benchmark preview \
  --index artifacts/cfunset/index.jsonl --topic "我的网购经历"
```

如果本机配置了失效代理，下载命令可加 `--direct`。下载器按 8 MiB 范围续传，完成后检查 218,997,952 字节和 SHA256。`prepare` 流式读取 JSON，生成 `index.jsonl` 和相邻的 `index.stats.json`，记录数据版本、原文件哈希、任务计数、去重计数与划分计数。

v1整理协议的验证结果：164,200 条源记录，过滤 150,728 条，精确去重 963 条，保留 12,509 条候选；其中训练 11,236 条、验证 1,273 条。保留记录中笑话续写 9,774 条、关键词笑话生成 2,735 条。这些数字来自代码的启发式规则，不代表原数据集的官方任务分布。

2026-10-21的v29盘点发现旧导入器只识别“生成一个关键词为……”，漏掉3,451条“生成一个主题为……”源记录。已补齐两种指令，规范化相同的示例仍按原规则去重、分组；新整理协议为 `cfunset-references-v2-topic-alias`。本机另存 `artifacts/cfunset/index_v29.jsonl`，保留14,002条参考（训练12,572、验证1,430），比旧索引增加1,493条；核验旧12,509条的正文、ID和划分全部保留。旧 `index.jsonl` 及历史实验没有覆盖，新索引尚未用于生成效果对照，不能由条数增加推断更好笑。使用它时指定 `--index` 或 `--cfunset-index`，并使用新的实验输出路径。

原文件按指令盘点包含31,424条笑话生成／续写记录（关键词9,561、主题3,451、续写18,412）、1,452条幽默解释、7,808条相声续写、4,200条幽默识别、119,316条相声回应选择，总计164,200。这里是任务记录数，并非独立好笑作品数。对第一轮生成微调实验，数据规模具备可行性；仍需按训练目标处理混合任务、检查近重复及数据质量，不能把目前的短参考索引直接等同于最终SFT训练集。

仅保留关键词笑话生成和笑话续写中适合短篇单口参考的样本。相声多选应答、幽默解释、分类不作为生成样例。清理时限制长度、检查中文字符、过滤明显粗俗或课堂不宜内容，按归一化铺垫与结尾的 SHA256 去重；同一哈希按模 10 固定分到训练（90%）或验证（约 10%）。检索只读取训练划分。关键词生成样本取末句作为**包袱候选**；续写样本使用第一句及续写作为**铺垫和包袱候选**。这是程序的启发式切分，CFunSet 原文没有这些金标签。检索使用主题和常见相关场景词与样例的短语匹配、汉字二元组重叠，并排除过于相似的铺垫。自动过滤不保证适宜性，正式展示前仍需人工抽检。

## 生成流程

初版流程中，`ComedyDirector` 将简短主题展开为五个生活场景，`JokeWriter` 按约 250 汉字/分钟设目标长度，并硬性要求至少 `分钟数+2` 组 `[SETUP]`→`[PUNCHLINE]` 和两次 `[CALLBACK]`。这套数量规则已在 v16 移除；当前流程见下文“v16：短笑点与经历，两种起点”。`PerformanceCoach`、`QualityController` 和返工路由仍沿用 AutoGen 0.2 工作流。

根据首轮评分反馈，共享提示加入校园场景核对：住校大学生赶早八默认在宿舍与教学楼之间步行或骑行；若同时出现地铁，须说明走读或跨校区的理由。该约束对两种生成条件一致。已保存的首轮十条轨迹产生于加入此约束之前，不能作为修正后的效果评估；聚合结果和限制见 [CFUNSET_RESULTS.md](CFUNSET_RESULTS.md)。

R1 单人评分之后，旧版写作提示加入“具体新信息完成反转、避免解释笑点、控制弱包袱数量”的要求；当时的程序还硬性检查双回调和早八地铁场景。双回调数量检查已在 v16 移除，早八通勤仍按题目具体语境核实。第二轮小样本发现词面相关的短笑话仍可能低质或过时，因此第三轮从训练集检索最多 12 条候选，经一次低温 JSON 模型筛选后最多给 JokeWriter 两条，允许全部淘汰；同时检查脚本长度上限。第六轮将候选池扩到 30 条；这些是历史迭代记录。筛选结果是模型判断，不能当成人工幽默标签，所用示例 ID 记录在轨迹中。设计依据与局限见 [HUMOR_QUALITY_RUBRIC.md](HUMOR_QUALITY_RUBRIC.md)。

两种生成条件使用同一模型、温度、主题扩展、脚本协议与质检流程：

- `baseline`：不提供 CFunSet 示例；
- `cfunset`：从训练集候选中挑最多两个可迁移的结构参考给 `ComedyDirector` 和 `JokeWriter`，明确要求学习结构而非复制原句；候选筛选另调用一次模型 API。

真实生成需要项目既有的 OpenAI-compatible 配置。将 Key 写入 Git 忽略的 `.env`，例如 `OPENMIC_API_KEY`、`OPENMIC_BASE_URL`、`OPENMIC_MODEL`。命令行示例：

```bash
openmic --backend autogen --content-mode baseline --topic "我的网购经历"
openmic --backend autogen --content-mode cfunset \
  --cfunset-index artifacts/cfunset/index.jsonl --topic "我的网购经历"
```

Streamlit 页面也有“Prompt baseline / CFunSet 检索增强”选择和索引路径输入。Mock 后端仍用于不消耗 API 的流程演示，不代表真实生成质量。

## 训练本地评分器与自动返工

CFunSet 的 4,200 条“是否具有幽默性”样本是短文本二分类数据，**不作为生成示例**，单独训练一个字符二元/三元特征的 Bernoulli Naive Bayes 模型。训练命令：

```bash
python -m openmic.humor_scorer \
  --source artifacts/cfunset/CFunSet.json \
  --output artifacts/cfunset/humor_scorer.json.gz
```

训练脚本核对固定数据 SHA256，按归一化文本去重并排除标签冲突；相同文本只能进入同一划分。哈希固定划为 train/validation/test，验证集只用于概率校准，测试集不参与拟合。权重和原始语料保存在 Git 忽略的 `artifacts/`，仓库只提交训练代码与汇总指标。该模型估计的是**CFunSet 短文本被标为“幽默”的概率**，不是三分钟单口的人工 1–5 分幽默度。

独立质量闭环在 `openmic.humor_quality_loop`：默认先提出五个不同核心情境，由另一模型独立给日常逻辑、偶然性、人物冲突和揭底各打 1–5 分；至少一个情境四项都达到 4 且无致命问题才扩写，第二轮会读第一轮审稿理由。若两轮都不通过，保存 `failure=no_premise_passed` 并停止，避免把弱想法扩写成三分钟流水账；可用 `--no-premise-search` 关闭这一步。获准情境送入现有五 Agent 生成，再把每组铺垫包袱送入本地模型；程序硬查标签、回调与时长；两次独立的 DeepSeek 审稿分别评包袱/文化/口语/结构及现实流程/跨段连续性。具体问题须附对应组号和脚本原文；未通过则让 JokeWriter 以固定 JSON 铺垫/包袱格式改写。若同一情节反复失真，可换全新日常冲突；若只有几组弱包袱，可只改被点名的组。所有候选和审稿记录逐步保存，择优时先看结构与现实问题，再看评分；本地分类概率只作末位参考，不能覆盖真实流程错误。

```bash
python -m openmic.humor_quality_loop improve \
  --topic "宿舍洗衣房排队" --content-mode cfunset \
  --index artifacts/cfunset/index.jsonl \
  --scorer artifacts/cfunset/humor_scorer.json.gz \
  --review-model deepseek-v4-pro \
  --output artifacts/quality_loop_laundry_v1.json \
  --max-rewrites 2 --max-replans 1 --max-surgeries 1
```

生成模型仍由 `.env` 的 `OPENMIC_MODEL` 指定；`--review-model` 可让独立审稿和改写使用另一个可用模型 ID。输出 JSON 会保留每次候选与双审稿；中断后同一路径可续跑，同一实验的模型与协议不匹配时会拒绝混写。也可用 `--seed-script` 从已有稿件开始，节约重新生成的 API 花费。模型审稿和本地分类器都有偏差，最终效果仍须新主题的人类盲评确认；若没有候选达到门槛，命令会明确输出 `accepted=false`。小样本验证及失败案例见 [CFUNSET_RESULTS.md](CFUNSET_RESULTS.md)。

R1 的新评分揭示食堂试验的两篇盲评稿有约 95% 文本重合，实际上只是原稿和局部修订，不能当作两篇独立笑话。制作新的同主题盲评表后先运行 `python -m openmic.humor_quality_loop check-pilot --sheet <CSV路径>`；同主题任意两篇超过默认 82% 相似度会拒绝评审，已填分的旧表不要覆盖。`r1-feedback-v8-campus-realism` 把普通白天去教学楼上课默认写成直接进楼；特殊房间/时段门禁需要先核实并交代，不能临时发明闸机作为包袱。当前质量闭环标记为 `r1-feedback-v9-premise-search`，增加扩写前的核心情境筛选；独立审稿达到幽默 4/5 且没有阻断问题才自动通过。这些门槛是筛选策略，不是已经验证的人类质量提升。

## 量化评估与盲评

### v10：公开表演机制与双路径情境

v10 时质量闭环协议为 `r1-feedback-v10-reference-mechanisms`。情境提案同时尝试「普通细节重解」和「单次小意外」两条路径，每轮五条、每种至少两条；独立审稿把原来的“偶然性”改成“触发点自然度”。这些路线配额与偶然次数限制均已在 v16 移除。第二轮须更换前一轮的触发与应对动作。研究来源、借鉴边界与失败案例见 [COMEDY_REFERENCE_MECHANISMS.md](COMEDY_REFERENCE_MECHANISMS.md) 和 [CFUNSET_RESULTS.md](CFUNSET_RESULTS.md)。不同协议的结果不混算。

### v14：具体语境、CFunSet 机制迁移与观察型冲突

v14 的生成协议为 `r1-feedback-v14-observation-externality`。现有 `openmic` 命令和 Streamlit 表单可输入具体语境；主题、人物关系、事件顺序与限制传给五个 Agent。用户已给出真实事件时，质量闭环直接围绕事件写稿，跳过另造情境的预筛选。只输入短主题时，预筛选优先找四维均 ≥4 的情境；若没有，可选日常可信与触发点 ≥4、冲突和揭底 ≥3 的**开发性情境**扩写，但成稿仍须通过独立幽默与现实审稿，不能把情境通过当成稿件通过。

主题扩展现在从一次自然小意外或普通细节重解出发，五个节拍沿同一事件链推进；人物选择、另一人的正常目标和可见后果产生升级，不要求每段重新发生巧合。CFunSet 筛出的最多两条训练样例同时提供给导演与编剧，导演先抽取铺垫、揭底和口语节奏的可迁移结构，再按新主题创作。筛选器读取具体语境；梦境或抽象比喻若有可转译的预期落差，也可以作为机制参考，但成稿必须还原成可信的日常动作与人物选择，不能照搬设定或台词。允许全部弃用。CFunSet 原始文本不提交仓库，所用样例 ID 保存在忽略目录的轨迹中。局部修订改变事件后可同步修订回调；独立事实审稿逐条核对回调是否仍受前文支持。

若用户题目**明确**要求穿越、古代或梦境，生成器允许这个统一幻想前提，以现代人不自觉掏兜找手机、期待便利设施等熟悉习惯制造错位；事实审稿检查人物知识、物品状态和已建立世界规则是否一致，不因穿越本身扣真实感分。普通宿舍等现实题材仍须遵守现实流程。对“薛定谔的猫”式比喻，只借“想确认充电又不敢碰手机”的矛盾动作，将其扩成可见的应对与反作用，不把术语本身当作包袱。

观察型题材还有一条不同的有效路径：先建立观众共同讨厌的声音或日常动作，再揭示**承受代价的人与享有成果的人不同**，让同一细节在结尾获得新的含义。此路径无需硬加偶然事故或人物争吵。它来自用户对[周奇墨公开装修片段](COMEDY_REFERENCE_MECHANISMS.md)的逐段反馈；只借结构，不复制原表演情节或台词。`minor_chance` 路径在 v14 曾要求一次小意外后由人物选择推动冲突；v16 已移除此数量限制。

### v16：短笑点与经历，两种起点

用户对 v15 稿件给出幽默度 4/5、结构完整 5/5，并肯定人物想象帮对方捡卡后交上朋友的内心戏；认为后段突然让室友在朋友圈回复使结尾生硬。另一模型的评语也指出脚本把普通过渡句标成 `[PUNCHLINE]`、解释冲突过多、结尾像总结句。v16 因此允许两条创作路径：先有一个有效的短情境笑点，再补出人物与事件；或先有一段经历，再提炼冲突和笑点。两条路最后都要形成说得通、好讲述的一件事。

主题扩展不再按固定五节拍规划，编剧不再按时长填固定数量的铺垫包袱与双回调。结构标签只标实际建立与打破预期的位置；自然回收前文细节才标回调。程序的硬检查只保留标签可解析、成对、非空回调和时长上限；标签数量、延迟与回调仍记录为**诊断指标**，不能当成幽默度。情境提案允许 `joke_first` / `story_first`，不再强制语言路线配额或只准一次偶然。独立审稿先判断整段故事效果；符合人物性格的内心预演与现实偏差可直接形成笑点，必要铺垫不因缺少独立事故而被打回。事实核查仍检查物品、时间、人物行为和场地规则是否可信。新协议为 `r1-feedback-v16-story-first`（名称为历史标识，两条创作路径均可用）；旧实验不与 v16 混算。上述是**方法改动**，尚无 v16 人工评分验证效果。

### v17：笑点强度与故事合理性分开审

一份外部模型对 V16A 的评语给出 6.5/10：肯定开头“卫衣才是身份证”、认错后的内心纠结和真室友就在旁边的转折，但认为肩上恰有灰是方便主角解围的巧合，末尾重复拍灰借口，整篇更像容易理解的幽默故事而非足够好笑的单口。此分数不是现场观众或用户本人盲评分。

v17 保留 v16 的两种创作起点，不设笑点、偶然或回调数量门槛。编剧会试着比较“没有替主角解围的巧合，人物下一步动作是否更有趣”，并压缩只解释故事或重复比喻的句子。质量审稿分别看因果真实与具体笑感：故事顺畅不自动抬高幽默分，纯粹复述旧借口的回调也不加分。自动返工接收整篇审稿总结，并拒绝几乎只改标签的版本。以上是可检验的写作与审稿假设，不保证生成质量已提升。

### v18–v20：物品状态与短稿

“用盆排队”实验暴露事实核查漏检：上一位衣服未取，新一位的衣服却在同一台机器里转；主角未洗的衣服在结尾又被称为湿衣服。现在洗衣房情境的提案和事实审稿会明确追踪上一锅如何取出、主角衣服何时接触水；程序还对“无人取出旧衣、下一锅已启动”的明显组合给出阻断诊断。该定向检查不保证能识别所有措辞或其他领域的状态矛盾。

用户允许短故事短讲。`duration_minutes` 现在可选 1–5 分钟，CLI 的 `--duration` 与 Streamlit 时长选项同步；参数表示**上限参考**，不要求填满。默认仍为 3 分钟。生成器在事件只支持一两处有力笑点时可直接收住。JokeWriter 偶尔把 PerformanceCoach 的 `[EMOTION]`、`[PAUSE]` 和 `<SCRIPT>` 复制回来，工作流现会清理这些表演标签后再审稿或输出，仍保留 `[SETUP]`/`[PUNCHLINE]`/`[CALLBACK]`。没有选中 CFunSet 参考时，Agent 不得声称使用“参考1/2”；轨迹继续记录真实样例 ID。质检输出“修改意见：无”也不会被误当成返工要求。

v20 进一步提示：用户若已给出故事转折，编剧应寻找人物当场的新动作或自然对白；找不到更有趣的下一句，就停在转折处。不能仅把已知转折重新说一遍。方法和实验详见 [CFUNSET_RESULTS.md](CFUNSET_RESULTS.md)。

### v33–v34：主题优先检索、保留原梗与增益检查

v35 阶段协议为 `cfunset-craft-v35-absolute-humor`。检索在训练参考内统计词频、文档频率，以主题优先 BM25 评分，语境只辅助，避免“上课”题因语境里提及手机而被充电器样例占满。近例筛选使用专门提示，完整原文和筛选错误均留痕；三题实测已选中并完成改编。

根据源例对照编辑反馈，改编可以保留或压缩，不默认扩写。质量闭环追踪角色身份与后果；低质量扩写先尝试只改必要语境，再在预算内尝试新故事。v35 根据后续用户反馈取消非负增益门槛，按成稿绝对幽默度筛选：即使略逊于优秀原例，只要仍好笑且合语境即可保留。`--compare-source` 可额外做交换顺序的增益诊断，不影响接受与排序。它仍是模型诊断，不代替真人笑感。详见 [任务二优化与验收边界](TASK2_OPTIMIZATION.md)。

v36–v37 区分大学生受众和校园故事，默认保留原例关键地域、时代与梦境；两项实际回归已保住古装梦和东北冬天。当前 `cfunset-craft-v37-script-evidence` 在中长稿独立评审中提取实际正文的揭底/回收引文，核验位置及依赖；不向该审查提供导演计划，也不凭层数加幽默分。健身房开发稿目前检出两处候选回收、深度1，未证明多层自然回调或人类笑感提升。

### v30–v32：源例机制、揭底计划与近例改编（历史）

最新实现与证据边界见 [任务二优化与验收核对](TASK2_OPTIMIZATION.md)。机制卡只描述原例中的预期、实际转折原句和意义变化，不生成未经验证的新场景操作。导演计划中的回调锚点、依赖深度与成稿字面实现分开记录，不能把计划中的回调当作已生成的效果。

新增允许近似原例的改编分支，优先保留核心事件、因果和包袱，仅改兼容细节，明确记录来源。v32 时普通 CFunSet 流程默认以 0.35 概率尝试，v39 调整为 0.25；无法选中原例则回退自主创作；`--adaptation-probability 0` 关闭、`1` 强制尝试。标准生成对照实验固定为 0。较早章节的“不可照搬”指引仅适用于自主创作；近例改编分支允许相近措辞。此分支不是模型权重训练；本节v32的两次实测均回退，后续验证见 TASK2_OPTIMIZATION.md。

### v27：创作提示审查与角色分工

删去了共享提示中让各 Agent 显式引用上游结论的要求，编剧直接应用素材；与当前场景无关的常识不再反复注入，例如扶门题不提示早八地铁。导演提供两条具体可说出口的笑法，而非只说“有反差”；受众分析补充熟悉的生活细节并指出明确矛盾，不替编剧规定唯一结尾。编剧从人物当时知道什么、想维护什么出发，可以用行动、内心独白或贴切比喻改变预期；不要求每次都增加事故。CFunSet 参考说明缩为预期变化与节奏，移除把所有梦境/比喻参考套成同一机制的长说明。

标注放在成稿之后，正文可以只有一对铺垫包袱。清理器删除多余/未配对的结构标签但保留所有可朗读文字，避免为纯标记问题调用模型重写；没有任何可解析结构的稿仍不通过协议检查。独立质量闭环让五 Agent 只出一轮稿，后续由独立审稿控制 `max_rewrites`，避免内外两层各自返工。普通页面的五 Agent 返工上限保持其原配置。

这些修改中，去掉多余返工和标签修复有离线验证；创作效果只有两题单次同题盲比和一次完整流程复测。前者的模型偏好较好，后者幽默仍为 3/5，尚不能宣称人类笑感已提高。完整证据见结果文档。

例如：

```bash
openmic --topic "宿舍借充电器" --context "手机剩2%，室友桌上的充电器是我昨天借给他的。"
python -m openmic.humor_quality_loop improve \
  --topic "宿舍借充电器" \
  --context "手机剩2%，室友桌上的充电器是我昨天借给他的。" \
  --review-model deepseek-v4-pro \
  --output artifacts/quality_loop_charger_v12.json
```

CLI 默认输出可读的最终脚本；`--verbose` 才显示完整 Agent 轨迹。质量闭环会保存全部候选与失败原因，`accepted=false` 时不能把最高分稿当成已验证的好笑作品。有关新版本真实试验，见 [CFUNSET_RESULTS.md](CFUNSET_RESULTS.md)。

本地 `artifacts/cfunset_reference_review_v12.csv` 保存两条曾被选中的充电器相关参考原文和待填评分栏。可分别给原例幽默度、机制可迁移性、宿舍情境适配度打 1–5 分，并写明可借用的冲突、问题和改写建议；这张素材表不是生成稿盲评，也不进入 Git。

```bash
python -m openmic.humor_benchmark compare \
  --index artifacts/cfunset/index.jsonl \
  --output artifacts/content_benchmark
```

固定五主题：我的网购经历、食堂排队、赶早八、地铁通勤、手机电量焦虑。每个主题各跑两种条件，保存 Agent 全轨迹、脚本、模型质检分、返工次数和可检查的结构指标。结构代理分数（0–10）由成对标签数、延迟铺垫数、相隔一定距离的回调及字数偏差组成；它**不能替代真实幽默度评分**。`blind_rating_template.csv` 打乱条件顺序，`blind_key.json` 单独保存对应关系。给至少两名不了解条件的评分者复制/填写表格，分别按 1–5 分给幽默度、文化适配、口语自然度、结构完整性评分。不要把 `blind_key.json` 给评分者。

盲评统一使用以下锚点：1 分表示明显缺失或不适宜，3 分表示基本可用但效果不稳定，5 分表示稳定且适合校园舞台；2、4 分位于相邻锚点之间。幽默度看包袱是否产生意外且有效，文化适配看中文校园语境是否自然、是否冒犯，口语自然度看是否能顺口说出来，结构完整性看铺垫、延迟抖落、递进和回调是否清晰。每位评分者独立复制同一模板，填写全部十条、自己的 `rater_id` 和四项分数；最后把数据行合并到一个 `ratings.csv`，只保留一个表头。

`compare` 每完成一条样本就追加一行轨迹；中断后使用同一输出目录可从下一条续跑。续跑前会核对模型、数据版本、随机种子和轨迹顺序；改变实验条件时请使用新的输出目录。如果脚本或质检响应不完整，会最多重试三次，仍不完整则报错且不写入该条轨迹。

额度有限时可加 `--max-samples 2`，先生成首主题的一对稿件；之后去掉该参数并使用**同一个输出目录**续跑。十条全部完成后才会写正式盲评模板；自动汇总仍需单独运行 `auto-summary`。保存生成日志时在 Windows 先设 `PYTHONIOENCODING=utf-8`；给 Excel 打开的 CSV 应采用 UTF-8 BOM。

首轮实验目录使用旧生成协议。R1 后第一轮提示改进标记为 `r1-feedback-v2`，下一轮筛选与长度控制标记为 `r1-feedback-v3-curated`，有效回调和包邮/自提常识版标记为 `r1-feedback-v4-callbacks`。`r1-feedback-v5-qc-routing` 进一步把质检文本中明确列出“修改意见”或“不合常理”却给 `APPROVED` 的结果送回写作 Agent，返工上限仍为两次。`r1-feedback-v6-situational` 加强逐段日常真实感、偶然差错与冲突检查，并扩大检索候选池。`r1-feedback-v7-one-throughline` 要求单一主目标、主线物品与相邻场景状态连续；基准对照当前 `r1-feedback-v8-campus-realism` 再处理教学楼门禁常识与流水账式弱包袱，质量闭环另加 v9 情境预筛选。不同协议须使用不同 `--output`，不能在旧目录混写轨迹。首轮旧轨迹仍可直接用 `auto-summary` 离线汇总。

十条轨迹完成后可运行 `python -m openmic.humor_benchmark auto-summary --traces artifacts/content_benchmark/traces.jsonl`，生成 `automatic_summary.json`。它按五个主题计算 baseline 与 CFunSet 条件的结构代理分、铺垫包袱数、回调数、字数，以及模型自评幽默、文化、结构分的配对差值；这些模型自评分仍不能替代盲评的幽默度与文化适配度。

完成评分后运行：

```bash
python -m openmic.humor_benchmark summarize \
  --ratings artifacts/content_benchmark/ratings.csv \
  --key artifacts/content_benchmark/blind_key.json
```

结果报告每个条件各维度样本数、均值与样本方差，并在报告中附上评分人数、失败案例与模型/数据版本。`compare` 需要真实模型 API 和时间；在实际运行并收集评分前，不应把指标写成实验结论。检索是词面匹配，可能漏掉同义表达；基于末句的候选包袱也可能误切，人工需抽检验证划分。
