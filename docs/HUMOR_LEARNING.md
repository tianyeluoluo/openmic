# 中文笑话语料学习实验（v28，2026-10-21）

## 目的与实际训练范围

目标是提升课程任务二的真实笑感。CFunSet 仍是主数据集；本实验增加带人工幽默等级和手法标签的正例，检验能否补充“幽默／非幽默”二分类缺少的强度信息。

本次已经在本机 CPU **实际拟合**了幽默等级回归器和八类幽默手法分类器。语义模型使用冻结的 BGE-small-zh-v1.5 表征，训练 Ridge 和 Logistic Regression 输出层；另训练字符 TF-IDF 基线。**没有微调 DeepSeek，也没有训练新的生成大模型。** DeepSeek 仍通过 API 接收示例与提示生成内容。

CMHL 的[原论文](https://aclanthology.org/2020.lrec-1.168/)明确指出：每条笑话只有一位标注者；幽默等级与读者反馈的相关性较弱。高分标签可用于发现候选，不能当作“满分集合”。不少旧笑话也不适合今天的校园单口。

## 留出测试结果

幽默等级是原语料的 1–5 标签。MAE 越低越好，Spearman 越高越好。

| 模型 | MAE | Spearman | 高分≥4／低分≤2 AUC |
| --- | ---: | ---: | ---: |
| 恒定训练均值 | 0.8296 | 0.0000 | 0.5000 |
| 字符 TF-IDF + Ridge | 0.7864 | 0.2667 | 0.6615 |
| 冻结 BGE + Ridge | 0.7982 | 0.2201 | 0.6340 |

八类手法分类：字符模型 macro-F1 0.3029、micro-F1 0.4179；语义模型 macro-F1 0.2965、micro-F1 0.3521；所有类别都报“存在”的基线 macro-F1 0.2341。双关相对较易，反讽等少样本类别很弱。不要只与 F1=0 的全阴性基线比较并宣称很高提升。

**结论：这些模型学到了一些标签关联，但不足以可靠判断一篇新单口是否好笑。** 字符基线优于语义输出层，说明“换上语义编码器”也不自动解决幽默理解。本地预测不进入生成稿的通过门槛或优选排序。

与当前 CFunSet **生成训练索引**的规范化正文做精确匹配，发现 CMHL 有 19 条重合（CMHL 训练16、验证1、测试2）。本实验的新输出层未用 CFunSet 训练，但两个来源不能宣称互相独立；此检查未覆盖整个原始 CFunSet，也未覆盖改写和预训练污染。

## 对生成方法的改动

新增可选 `--humor-memory`，默认关闭：

1. 在 CMHL **训练集**中检索原标注为4或5、长度60–500字的叙述候选。不用本地预测分数挑高分，不取验证／测试笑话。
2. 编辑从最多8条候选中选零至两条，分别提炼“原先的理解—改变理解的信息—可迁移的机制”。同一机制不重复选；相同物品不够证明参考有用，可以全部弃用。
3. 导演与编剧获得这些额外正例。CFunSet 参考仍单独记录，不混称数据来源；其余受众分析、表演指导和审稿角色不接收原始正例。
4. 评分头仅输出有明确含义说明的诊断，不作为“笑得出来”的证明。检查点保存来源、候选、选中 ID 和模型哈希。

三题各一对的编剧单阶段试验：Flash 生成、Pro 匿名评审。额外正例条件在健身房和图书馆题被模型偏好，在理发题输给原流程。模型给新/旧幽默分别4/3、4/3、3/4，**不能当成人评或统计提升**。

人工诊断发现：健身房新稿把明显储物柜认成器械，动机牵强；旧稿依赖未交代的跑步机启动方式；图书馆新稿“念的是页眉”更具体，但页眉本身就是可见内容，未必真能证明装懂；理发两稿仍多为社恐共鸣而非强笑点。部分生成稿还未返回可解析结构标签。这些是保留实验开关而不替换默认流程的原因。

另跑了一次真实完整五 Agent 流程（图书馆题），CFunSet 选中2条、CMHL 选中2条，一轮5条Agent消息、未追加返工。独立幽默3/5、文化／口语／结构／真实感4/5，事实检查5/5、无阻断，`accepted=false`。稿中“食堂小票从第三页滑出／前面都在铺垫”说明流程接通，但小票与“装懂难书”的反转关系仍弱。这次集成测试没有证实质量提升。

本轮54项相关单元测试通过：新训练模块8项、生成提示16项、质量闭环18项、工作流12项。测试覆盖标注错位、重用ID、繁简冲突重复、近重复跨划分、模型保存加载校验、排除留出参考、拒绝虚构参考，以及额外正例只进入创作角色。单元测试不衡量真实笑声。

## 复现命令

在仓库根目录，使用有 API 配置的 Python 环境：

```powershell
python -m pip install -e ".[learning]"
python -m openmic.humor_learning download
python -m openmic.humor_learning train
python -m openmic.humor_learning inspect --text "图书馆看不懂一本难书"

python -m openmic.humor_quality_loop improve --topic "图书馆装作看懂一本难书" --context "还没看懂，认识的同学问起内容" --duration 1 --humor-memory artifacts/humor_learning --max-rewrites 0 --max-replans 0 --max-surgeries 0 --output artifacts/memory_demo.json
```

数据、编码器、拟合输出层及训练报告在忽略目录 `artifacts/humor_learning/`。下载保留数据集许可与引用；生成原文、用户评分和 API 配置不纳入提交。代码、测试和精简方法文档可以随以后正式版本统一提交。

## 后续优先事项

先以新题人评验证正例迁移是否改善笑感，同时单列生活合理性；不要继续追模型自评分。若继续训练生成模型，应先准备“语境→有真实笑点的稿子／解释”的合适训练对，并有独立人评留出集。CMHL 是短笑话理解语料，直接把所有正文当 SFT 答案不能保证学会按用户语境写单口；未经验证不启动大规模 LoRA。TalkFunny 值得后续核实获取与许可。用户已喜欢的内心戏正例可以用于开发，但不能同时当作独立测试。
