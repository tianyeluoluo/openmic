## CFunSet 近例改编

根据用户要求，增加保留原例事件与包袱、只改兼容姓名和地点的分支。它与自主创作分开提示，允许近似措辞，来源放在正文之外，不冒充全新原创。**近似改写不等于微调，也不证明模型已经学会幽默。**

普通 CFunSet 生成默认有 0.25 概率**尝试**改编、0.75 概率借鉴机制后自主创作；没有合适原例则回退，并保存理由。这个比例是分支抽样，不代表75%成稿必定具有某种形式或质量。0 表示自主创作，1 表示每次尝试改编，均不保证输出质量。CLI 使用 `--adaptation-probability`、`--adaptation-seed`；页面有对应概率滑块。普通工作流仍尊重 `OPENMIC_ADAPTATION_PROBABILITY`，显式参数优先；独立质量闭环按其CLI参数设置。标准 baseline/CFunSet 对照实验固定概率为 0，避免两种任务混算。

```bash
openmic --topic "去校门口买水果" --cfunset-index artifacts/cfunset/index_v29.jsonl --adaptation-probability 1
```

相似度指标仅描述字面相近；改编质量仍要核对原例因果、语境兼容性和笑感。未选中原例时不得做忠实度判断。

v34 不默认扩写：可以保留、精简，确有新回应或具体后果才扩写。审稿追踪实际行动者、对方以为的身份和后果承担者，避免把“替缺席者答题，职位落到缺席者名下”写成笼统的“我当班干部”。不在揭底前替听众解说答案，不用结尾换句话复述原包袱。

v35 按用户目标改为优先判断成稿的绝对笑感：强原例略有损失但改编仍好笑，可以接受。素材编辑先核对语境，再选揭底有效、必要铺垫少的原例；不按字面相关或扩写空间选故事。改编导演可只保留一条核心笑法，受众分析不再强制补两处细节或新笑法，减少无用扩写。

v36 明确区分受众与故事场景：面向大学生不要求校园化，原来的人物、职业、地域和梦境可以保留。文化分看中文语境及听众理解门槛，校园名词不加分；用户明确指定校园或纯写实时才遵循其场景约束。近例忠实度增加1–3项支撑反转的必要前提检查与引文核验：任一前提被判定丢失，即使总评写核心保留，程序仍判不保留。这样可拦截已被评审识别的“梦境古今错位改成主动演戏”“极寒背景缺失”等问题；模型仍可能漏识别，不保证自动理解完全可靠。

v37 实测中，充电器稿保留了古装梦境，啤酒稿保留了东北冬天背景。另修复跨结构标签的正确引文被误拒，以及开头在首个SETUP前后完全重复的问题；后者仅删除逐字重复的开头，不删不同的开场。

v38 为CFunSet机制卡补充 `information_flow`：人物或听众、此前理解、揭晓后理解、连续原文证据。每个已选原例须有1–3条；引文必须来自该原例。兼容顶层返回时，只在引文唯一对应一个已选原例时归属，不能猜测。卡片实际传给导演和编剧，仍标为模型推断，不作为原数据金标签，也不包含替新故事编造的设备或后续行动。

生成和事实检查增加人物信息连续性：没有听到的承诺不能自动知道；已经知道真相后可以打趣、配合或装不懂，但应有线索。审稿区分一致、含糊、明确矛盾；只有明确破坏情节且有前后原句证据的矛盾进入阻断问题，含糊不自动判失真。合理内心戏继续保留。

时长至少2分钟的独立质量闭环增加一次成稿结构审查，不向该审查提供导演计划。程序核对正文引文和先后顺序；无效事件被剔除并列明原因，下游不能借它增加层数。数字/字符串ID统一处理，避免格式差异误丢证据。是否有新含义仍是模型解释，引用存在不代表真正好笑。这个诊断不为候选排序加分，不要求每篇短笑话都有回调。

普通五 Agent 质检要求幽默至少 7/10、三项均分至少 7/10，程序也检查，文化和结构高分不能掩盖幽默不足。独立质量闭环保留原先幽默至少 4/5 及事实、语境检查；通过语境检查后，候选先比较幽默，再比较其他维度。两套量尺来自不同提示，不将 7/10 与 4/5 自动换算。模型分数仍需人评验证。

最后的 `grounded-rubric-v17-short-joke-fairness` 提醒：一个有力揭底的短笑话也可得4或5，不能仅因没有后续、第二次反转而压分；力度弱仍应具体解释。此条来自实测评分理由里的数量偏好，尚未用新一轮API重新评这几篇，保留旧分数，不改写结果。

现有质量闭环在近例改编较弱时先尝试最小语境适配；它直接保留原梗，程序合并结构化铺垫与揭底，不要求与旧稿大幅不同。仍未通过时，在 `max_replans` 预算内尝试同语境自主创作。每份候选分别保存来源，最终选中新故事时清空改编 ID；失败稿不删除。

```bash
python -m openmic.humor_quality_loop improve --topic "冬天去饭馆点啤酒" --duration 1 --index artifacts/cfunset/index_v29.jsonl --review-model deepseek-v4-pro --adaptation-probability 1 --max-rewrites 1 --max-replans 1 --max-surgeries 0 --output artifacts/quality_v37_beer.json
```

`accepted` 是模型与程序检查结果，不能解读为真人保证好笑。重复运行相同输出路径会检查协议和状态；修改主题或协议时使用新路径。CLI 索引参数优先于 `.env` 的 `OPENMIC_CFUNSET_INDEX`。

## 边际喜剧增益与评审边界

同一量尺下，增益等于改编幽默分减原例幽默分。**v35 将此项降为可选诊断，不参与接受、排序或修订反馈；负增益也不单独淘汰。** 增益很高但本身不好笑的稿件仍不能通过。普通质量闭环不再自动花两次 API 调用比源例；需要研究原梗损失时显式加 `--compare-source`。

诊断时，原例和稿件去掉结构标签后，以匿名 A/B 以及相反顺序分别评审，程序汇总均值和次序一致性。只有两个顺序都支持正增益，才记录模型支持增强；这不影响稿件是否可用。两次判断来自同一模型，不能充当两个独立评分者。

忠实度评审的引文必须来自真实原例和稿件；原例为空时不调用评审。对明确的一位数乘法口诀，程序提供算术核对给评审，避免将“三六十八”误说成错误；这些计算不会传入创作提示提前泄露包袱。覆盖范围有限，仍需人工检查语义与故事逻辑。格式错误和无效引文最多补问一次，保留失败响应。

## 2026-10-21 本地实验

- 初版 v30 与 v29 在三个主题、相同参考样例下运行完整五 Agent 流程。独立模型盲比两胜一平：借笔记和约早起较好，扫错洗衣机持平。样本很少，尚无人类盲评分，且 v30 的机制迁移建议后来又删改，不能将结果直接记到最终 v32 上。
- v32 两次强制尝试近例改编均未选中兼容原例，实际回退自主创作。近例改编效果**尚未验证**。实验审稿曾在原例为空时编造原例内容，相关忠实度结论已作废并保留记录；现已在实验脚本拦截该情况。
- v33 修复语境里“手机”扩展词压过课堂主题的问题，并分离近例筛选提示后，三个题目均选中原例并完成改编。对应三份自主创作被单次模型比较评为 4/5，近例稿为 3/5；其 A/B 次序和后续评审错误限制了这个判断的可信度。
- 用户提供的编辑评语将买水果原例/改编评为 7/5（10分制），替课为 7.5/6.5，指出解释性扩写和身份后果错位。它属于开发反馈，不是新的独立盲评数据，不能与模型1–5分直接混算。
- v34 在固定旧原例的两个开发题上复测，并增加理发新题。另测两份最小改编。双顺序评审中，两份最小稿平均增益均为 0；水果扩写的排序随次序翻转，平均增益 0。其余两份模型给正增益，但文本解释仍有误读，尚无新增人评证实提升。理发题早先单次评审还曾给负增益，体现模型评价不稳定。
- 一个独立长稿试验获得模型幽默4/5和程序通过，但只有一处显式回调，不能当作已验证的多层回调样例。稳定笑感、多层成稿证据仍是下一阶段重点。

实验轨迹、源例全文和盲评阅读稿保存在本机研究工作区；原始语料和私钥不进入 Git。此次改动留在本地，等待较大的版本更新再提交小组 PR。

## 2026-10-23 信息差与数据利用验证

初测三题后发现模型把信息差数组放在顶层，程序当时未传递该字段；这些初测不算验证了新参考卡。修复字段归属后，对省钱和健身房两题各再运行一次完整流程，实际保存3张CFunSet卡、4条信息状态推断。另保留超市短稿供阅读。三个最终试读样本的原始模型幽默均4/5，但无新人评，生成随机性、选例与题材混在一起，不能归因于新方法或宣布统计提升。

两项人工构造的回归探针中，审稿拦住了“教练凭空知道私下承诺”，并允许“已经知道洗澡目的、仍打趣夸出勤”的合理对话。前一次探针因时间线数组数目错误失败，已修提示并保留错误日志。这个2例结果只能作回归证据，不能代表一般检测准确率。全项目99项测试通过。

## 2026-10-23 人物逻辑与收尾（v39）

用户转交的编辑评价为v38的A/B/C给出幽默4/3/4、结构4/2/4。它指出B新增花800、对象必须补500缺少因果，C则能让同一人物的理财式自我辩解在多个情境中产生不同小包袱；建议C在续费“每天只亏两块五”处结束。这是开发反馈，不是独立人类盲评，不据此宣布整体显著提升。

据此，将近例改编的默认尝试概率从0.35调整为0.25，另外0.75走参考后自主创作；共享常量供工作流、CLI、质量闭环与页面使用，显式参数及普通工作流环境覆盖保留。中长稿优先探索人物习惯在不同处境中的发展，题材适合单一事件时照常选择事件路线，不强制每篇都写成C。

导演、编剧、情境筛选、质检及独立审稿统一允许同一人物逻辑串联多个相关情境，不把切换情境本身当事实漏洞；仍核查实际动作、交易因果、物品和人物知识。每次应有不同的选择、反应或代价，同一个借口换词不算发展。这个组织方式不要求大反转，也不让结构数量替代真实笑感。

编剧与审稿比较当前结尾和前一个已经能收住的位置，后文若只重复、解释或另起弱包袱可以直接删去，不要求再写替代结尾；有新笑感的后文则保留。内心戏、旁白、概括和贴合人物的旁枝不因形式而自动删除，也不把全文机械截在最强单句。

本次只修改提示及抽样默认值，并对已有C做有来源的本地删尾精修，**没有新API生成或重评，也没有训练模型权重**。原始轨迹和分数不改，不能把精修稿算独立样本或用旧分给它背书。新生成、审稿、修订和情境协议均已换版本，下次实测使用新输出路径；真实幽默效果及合理多层回调仍待验证。
