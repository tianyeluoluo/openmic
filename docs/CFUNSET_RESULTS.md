# OpenMic 文本生成 v1：五主题自动评测结果

日期：2026-10-19。该报告可用于小组代码评审和课堂 pre；所有幽默、文化、结构的模型分数都是**模型质检自评**，并非人工盲评。

## 实验配置

- 条件：相同的主题扩展、Agent 流程、`deepseek-flash` 模型和温度 0.7；唯一条件差异是 JokeWriter 是否得到最多三个 CFunSet 训练示例。
- 五个预设校园生活主题，每主题 baseline 与 CFunSet 增强各一条；目标长度约 3 分钟。共保存 10/10 条有效轨迹，固定盲评打乱种子 2025。
- CFunSet 固定版本 `39ded465de072b19d4b843e319d7dc85d704be5f`，原文件 SHA256 `b8535022560118a830acb8e550556aadcd37df27ba303795c8db1b2b88c006ab`。原始文本、检索索引、模型脚本及 API Key 均未提交 Git。
- 所有十条都得到模型质检 `APPROVED`；这并不保证输出满足机器可读结构规范。

## 必须解释的失效案例

“手机电量焦虑 / CFunSet”在一次返工后，最终 JokeWriter 脚本使用表演标注，却没有规定的 `[SETUP]`、`[PUNCHLINE]`、`[CALLBACK]` 标签。规则解析得到 0 组铺垫包袱、0 个回调，结构代理分仅 1.79；同主题 baseline 为 9.97，差值 -8.18。脚本仍有三幕和文字包袱，模型质检给出 `APPROVED`。因此，此处分数主要反映**格式协议失效与评测器依赖标签**，不能直接解释成内容缺乏幽默。它也说明模型质检批准和结构协议检查应分开执行；下一版需在返工后校验标签，不合格则要求重新格式化。当前报告保留原始失败，不删除或替换该样本。

另一个工程问题是“赶早八 / CFunSet”曾生成脚本但质检响应为空；旧逻辑错误写为 0 分。该无效轨迹已在本地备份并从正式轨迹移除，现有代码要求脚本和质检分项完整，最多重试三次且逐条续跑。正式第六条重新生成后通过检查。

## 人工评价与复现

本地忽略目录 `artifacts/content_benchmark/` 已生成 `traces.jsonl`、`automatic_summary.json`、`blind_rating_template.csv` 和单独保存的 `blind_key.json`。至少两名不知条件的评分者应独立给全部十条脚本的幽默度、文化适配、口语自然度、结构完整性打 1–5 分。评分完成前不应将上述模型分数写成真实观众效果。评审时注意脚本标记格式不完全统一，可能影响结构感知；后续可统一展示格式，并保留原始轨迹。

首位评分者 R1 已完成十条匿名条件评分，原始 `评分1.csv` 留在 Git 忽略目录。其**单人初步结果**（baseline → CFunSet，1–5 分）：幽默 2.8 → 2.8，文化适配 2.6 → 2.8；口语自然度 2.6 → 2.8，结构完整性 3.2 → 3.2。R1 表示对幽默和文化适配两项判断更有把握，因此这两项优先用于课堂讨论，另外两项作为辅助观察。每条件仅五条且目前只有一位评分者，不能据此判断稳定效果或人际一致性。评分表中的十条文本和样本编号已与空白模板逐行核对，四项分数均在 1–5 范围内。

R1 指出一个文化场景误区：校园住校生赶早八通常从宿舍步行或骑车去教学楼，旧生成稿却可能把早八与地铁直接相连。**上述十条实验是在修正前生成的，评分和自动指标保持原样。**修正后的共享提示要求导演、写作和质检 Agent 优先采用校园内通勤；若确实涉及早八地铁，先交代走读或跨校区等原因。早八主题的检索关联词也去掉了“公交”，加入“教学楼、步行、骑车”。这属于针对反馈的下一版改进，若要测量改进效果必须用新输出目录重新运行，不能把旧实验冒充为新提示的结果。

进一步的 R1 逐稿分析和公开资料核对见 [HUMOR_QUALITY_RUBRIC.md](HUMOR_QUALITY_RUBRIC.md)。以上五主题数值仍只代表首轮旧协议；之后的小样本不能与其混算。

## R1 反馈后的网购小样本

`r1-feedback-v2` 用新目录生成了同一主题各一篇。baseline 与 CFunSet 的汉字数分别为 644 和 903，结构代理分 9.72 和 9.59，模型质检均分约 8.27 和 8.00。R1 在匿名条件下对 baseline 给幽默 4、文化 3，对 CFunSet 给幽默 3、文化 4（均为 1–5 分）。R1 指出 CFunSet 稿有“包邮后买家却上门取货”的交易矛盾，且包袱反转偏弱。**这只是一对样本**；它说明模型自评及高结构代理分无法代替读者评价。交易常识已加入后续创作与质检约束，旧稿保留原状。

`r1-feedback-v3-curated` 加入候选筛选与字数控制后又生成一对网购稿。baseline / CFunSet 分别为 637 / 670 汉字，两篇均满足当时的标签计数检查；但 CFunSet 稿有一个空 `[CALLBACK]`，当时的结构代理分错误地给它回调信用。修正解析器后离线重算，两篇有效回调数为 2 / 1，代理分为 9.70 / 8.79；CFunSet 稿应被标为协议失败。该对尚无人类评分，不能声称幽默度改善。修复后的检查采用新协议和新输出目录，不追改 v3 原始轨迹。

`r1-feedback-v4-callbacks` 又生成一对网购稿：baseline / CFunSet 分别为 671 / 685 汉字、各有 2 次非空且相隔的回调、结构代理分 9.79 / 9.83，模型质检均分均约 7.67。两篇通过确定性结构检查。R1 随后完成四项盲评（baseline → CFunSet，1–5 分）：**幽默 2 → 2、文化 3 → 2、口语 4 → 3、结构 3 → 3**。R1 评论 baseline 反转弱且反复围绕“包邮”；CFunSet 稿写出不合常理的上门取件收费和工作人员擅用顾客包裹。两篇的结构代理接近 10 分，人工幽默都只有 2 分，说明形式齐全不能代表情节可信或好笑。这仍只是一位评分者对一对稿件的反馈，不能推断总体差异。

对 v4 两条质检文本离线检查，**2/2** 都存在“批准同时指出具体待改问题”的矛盾。当前 `r1-feedback-v5-qc-routing` 已将这种结果纳入返工路由，相关单元测试通过；它尚未重新调用模型，不能把该检出统计写成 v5 生成质量。

R1 最新要求每一小段扎根日常生活，在可信流程上引入偶然差错和人物冲突。`r1-feedback-v6-situational` 因此让主题扩展和写作逐段写明日常目标、可能发生的小意外、当事人的应对与具体后果；受众分析和质检逐段检查场景真实性，并禁止为笑点硬造收费或擅用顾客物品。CFunSet 候选扩大到 30 条后仍只选最多 2 条，筛选须优先真实购物流程与可迁移的情境反转。此处记录的是**已实施的修改**，新生成质量须由独立的新样本盲评确认。

v6 同题新生成 baseline / CFunSet 两篇，分别 658 / 674 汉字、结构代理 9.75 / 9.80、模型 QC 8.17 / 7.83，均获模型批准；其匿名评分表在本地忽略目录 `artifacts/content_benchmark_v6/pilot_blind_rating.csv`，**尚无新人工分数**。人工通读发现 baseline 从转接头取件突然转去退鞋，又出现未铺垫的第二笔订单；CFunSet 稿更连贯，但假定退货必须当面扫码、取件要学生证，未先交代服务或站点规则。v6 一次已批准的试生成把 `HUMOR_SCORE 7` 写成无冒号格式，旧解析器误判为缺分并重试；现已支持这种写法并通过回归测试。v6 结果说明逐段检查仍可能漏掉跨段主线和场地流程。

下一版 `r1-feedback-v7-one-throughline` 因此让导演只规划一个主目标和一条连续经历，写作逐组追踪物品、地点、时间与状态；若新增商品或任务，必须先铺垫并服务于同一冲突。质检增加相邻场景连续性核查，且不默认快递员可进入宿舍或特定取件凭证在所有站点通用。这是针对 v6 失败案例的协议改动；评估仍需使用新目录和人工评分。

## 本地模型训练与双审稿（2026-10-20）

官方 CFunSet 原文件里还有 4,200 条“幽默/不幽默”短文本分类记录。去重和冲突检查后有 4,186 条；固定哈希划分为训练 2,922、验证 429、测试 835。训练字符二元/三元 Bernoulli Naive Bayes 分类器，用验证集校准输出概率。**未见测试集**的结果：准确率 0.6934、平衡准确率 0.6374、ROC AUC 0.7522、Brier 分数 0.1962；测试集多数类基线准确率约 0.6084。模型权重仅保存在本地忽略目录 `artifacts/cfunset/humor_scorer.json.gz`。这些数字只衡量 CFunSet 短文本标签预测，不能写成单口幽默度预测准确率。

用已有人类评分的旧脚本作域外检查：v4 两篇人工幽默都为 2/5，本地分类器的逐组均值概率却为 0.9054 / 0.7507，显示高概率并不等于强包袱。新闭环因此把本地模型当弱筛选信号，另以独立模型审稿、现实流程核查和确定性协议检查作门槛。对 v4 的开发性回查能指出增强稿“上门取件加八块”和门卫拿顾客包裹垫桌脚；对 v6 的回查指出 baseline 突然新增退鞋/订单、增强稿未说明的交接与凭证规则及若干复述式弱包袱。旧稿和人类分数用于**定位失效和开发审稿规则**，不是优化后效果的独立测试。

一轮新主题“宿舍洗衣房排队”的闭环实验保留初稿和各次修订。自由文本改写曾丢结构标签；固定 JSON 组数、程序渲染及长度检查修复了格式，但候选仍反复出现机门、衣物所在位置的矛盾，`deepseek-v4-pro` 双审稿没有批准任何候选。随后新增“换故事线”与“只改被点名的几组”两种有界操作。另一轮“食堂排队”有五条候选，初稿 684 汉字且结构达标，独立审稿给幽默 3/5、生活真实感 4/5，但指出三处弱包袱；整篇重写和换故事线总体更弱，局部改写虽保住结构也尚未获得批准。该数据是**优化失败和质检行为记录**，不是质量提升证据。两篇食堂候选曾制成单人匿名评分小表，现已发现实验设计错误，详见下一段。

**2026-10-20 人工纠错**：该食堂小表的 Q01/Q02 其实是同一故事的原稿与局部改写；去掉结构标签和空白后相似度约 95%，不能视为两篇独立笑话，也不应让评分者重复劳动。R1 只评了 Q01：幽默 1/5、文化 3/5、口语 2/5、结构 3/5、生活真实感 2/5；评论指出笑点弱、普通教学楼上课却安排刷闸机。Q02 保持空白，整对**退出独立盲评比较**，原 CSV 留存而不覆盖。对应局部改写稿的自动审稿幽默 2/5、真实感 3/5，虽未批准，仍高估了人类的体验；旧独立审稿与事实核查还漏掉教学楼闸机细节。新 `r1-feedback-v8-campus-realism` 在创作、审稿和确定性检查中加入普通白天教学楼直接进楼的默认场景，并把自动通过幽默门槛提至 4/5，另提供 `check-pilot` 拦截近重复稿。上述只是针对已知错误的修正，**尚无新样本证明幽默提升**。

校方资料展示门禁存在于[预约研讨空间](https://dean.pku.edu.cn/web/rules_info.php?id=2)和[部分特殊时段或楼宇](https://statics.phbs.pku.edu.cn/uploadfile/2020/0225/20200225105634871.pdf)；这些特殊规定不能推出平时进普通教学楼上课必须刷闸机。项目以 R1 对校园日常的反馈为默认设定，若写特殊地点应明确交代并核实。

v8 以未参与该轮人工纠错的新主题“雨天拿错伞”做了一次有界运行（本地忽略目录 `artifacts/quality_loop_umbrella_v8.json`）：初稿、一次整篇修订和一次局部修订共三稿，均未过自动门槛。三稿独立审稿幽默都是 2/5，事实核查真实感均为 4/5；初稿和整篇修订分别有 6、5 个包袱阻断问题，局部修订降至 2 个，但新增人物行为缺少铺垫和道具状态矛盾。所有稿件结构协议达标，说明当前主要瓶颈是**偶然事件之后缺少有力而可信的戏剧反转**，不是标签或字数。未做人工盲评，不能把自动审稿分等同观众感受；该试验保留 `accepted=false`，不展示为质量提升。

v9 增加扩写前的核心情境搜索与独立评分。仍用“雨天拿错伞”作开发主题，`deepseek-flash` 提案、`deepseek-v4-pro` 审稿的两轮共十个情境，偶然性全部只有 3/5，没有达到四维均 ≥4 的门槛；故停止于情境阶段，**没有生成脚本**（`artifacts/quality_loop_umbrella_v9_premise.json`）。加强“一次偶然、后续靠人物选择”的提示后，`deepseek-v4-pro` 同时提案与审稿的两轮仍全部未过偶然性门槛（`artifacts/quality_loop_umbrella_v9_pro.json`）。再把第一轮低分理由明确反馈给第二轮提案，人物冲突评分有所改善，但偶然性仍全部 3/5（`artifacts/quality_loop_umbrella_v9_feedback.json`）。这验证了程序会**阻止弱核心情境扩写**，未验证它能选出高质量单口稿。评分来自模型自己，且同一主题反复用于开发，不能当独立效果评估。

在桌面仓库使用 `python -m openmic.humor_benchmark auto-summary --traces artifacts/content_benchmark/traces.jsonl` 可重算此表。人工评分合并为 `ratings.csv` 后，再按 `docs/CFUNSET_CONTENT.md` 运行 `summarize`。所有数值都来自已保存的十条轨迹；本报告没有复制 CFunSet 原文或生成脚本。

## v10：公开表演机制参考与双路径情境（开发性记录）

将[公开片段与作者写作课](COMEDY_REFERENCE_MECHANISMS.md)整理成五种可迁移机制，只向情境提案提供抽象结构，不存台词。候选同时覆盖日常细节重解与单次小意外，审稿把“偶然性”改为“触发点自然度”，并要求人物选择制造双向目标冲突和可见后果。

两次新题目调用使用 `deepseek-flash` 提案、`deepseek-v4-pro` 审稿。`artifacts/quality_loop_printshop_v10.json`（“打印店取小组展示讲稿”）两轮共十条，均未通过：第一轮冲突最高 3/5；第二轮仍多为 3/5，且反复使用前一轮情境。`artifacts/quality_loop_presentation_v10.json`（“小组展示上台前的最后一次练习”）两轮共十条，每条审稿均为日常逻辑 4、触发点 4、冲突 3、揭底 4；第二轮五条事实上与第一轮逐条相同。两次均 `failure=no_premise_passed`、**没有扩写完整稿**，也没有新人工评分；不能宣称幽默度提升。

第二次运行后加了程序级跨轮去重：比较触发事件与应对动作，发现重复即最多重提两次，仍重复就停止，不再为同一情境反复付审稿费。此去重和更严格冲突提示已通过单元测试，**尚未做新的 API 验证**。模型此前的 4/5 揭底评分不应解读成真正有笑点：例如出现投影笔控制幕布、手机震起粉笔灰等牵强因果；人工通读仍有必要。下一次若继续，应先用真实经历或更短的 30 秒段落做校准，再决定是否扩成三分钟，避免在弱核心故事上耗费 API。

## v11–v12：具体语境、素材迁移与回调事实核查

v11 开始接受具体经历作为不可违背的语境。开发题“宿舍借充电器”给定手机剩 2% 电、室友桌上的充电器其实是讲述者前一天借给他的，人物关系正常。模型自带质检曾给初稿幽默 8/10、文化 9/10、结构 9/10 并批准；独立审稿只给幽默 2/5，指出室友态度突变、反复客气和抽象的结尾。初稿、整篇改写和局部修订共三稿，最终 `accepted=false`，未做人工盲评。轨迹保存在本地忽略目录 `artifacts/quality_loop_charger_v11.json`。

该轮选中的两条 CFunSet 参考分别是古装梦境里忘带充电器、以及把充电接触不良比作“薛定谔的猫”。它们与输入词面相近，但不能直接提供真实宿舍的人物冲突。随后开发中的筛选一度过度排除了梦境和比喻；用户指出这两条仍可能启发预期落差或矛盾动作。v13 现在允许以**机制**方式考察它们，要求导演说明如何转译到现实场景，写作不得照搬原设定。本地 `artifacts/cfunset_reference_review_v12.csv` 留有原例和三个 1–5 分评分栏，等待用户就素材幽默度与可迁移性给出反馈；评分前不把这两例宣布为好或坏。

用户进一步指出两条原例的可扩写方向：古装题可写“现代人穿越后不自觉掏兜找手机、习惯即时便利”的连续行为；充电器比喻可扩成“想检查是否充上又怕一碰就断”的动作困境。v13 据此区分**现实题材**与**明确幻想框架**：前者只能抽取梦境例的机制，后者允许穿越设定但仍要求现代习惯、人物知识与世界规则一致。当前只是创作策略和审稿实现，未取得新人工评分。

另一开发题“大学生去理发店剪头发”的情境预筛选选出一个四维均达门槛的故事：想保留能扎的小马尾，摸到被剪短的后颈，理发师误以为还嫌长，越修越短。初稿与两次修订的独立幽默评分均为 **2/5**，最终 `accepted=false`；初稿 636 汉字，结构标签与两次回调齐全，但后段买帽子只是连续小麻烦，缺少可信而有力的揭底。局部修订把皮筋改成“掉在地上”，旧回调仍说它“弹到别人头上”，原事实审稿漏掉该矛盾。轨迹保存在 `artifacts/quality_loop_haircut_v12.json`，未做人工盲评。

针对这一真实漏检，下一审稿协议要求逐条返回回调支持性判断；局部修订在事实变化时可连同回调一起修改。用同一条矛盾稿重审，`deepseek-v4-pro` 明确引用回调原句，列出“掉在地上”与“弹到别人头上”冲突，仍给 `accepted=false`；记录在 `artifacts/quality_loop_haircut_v12_callback_reaudit.json`。这是**一个已知案例的回归验证**，不能证明新审稿对所有事实矛盾都有召回率。当前瓶颈仍是三分钟段落中真正强而可信的包袱，而不是结构标签；模型通过门槛之前不应对外宣称生成质量已提升。

## v13–v16：机制迁移、单故事与人评校准

“现代人穿越古代” v13 初次检索没有选中 CFunSet 参考，独立审稿幽默 2/5、六条阻断问题。检索允许古装梦境等参考作为**机制**后选中两条，独立幽默仍是 2/5、两条阻断问题。轨迹分别在忽略目录 `artifacts/quality_loop_timetravel_v13.json` 与 `artifacts/quality_loop_timetravel_v13_with_refs.json`。阻断问题减少不等于幽默提升，更不能由这一对样本推断检索的因果效果。

“认错人拍背” v15 写成图书馆门口提醒前方陌生人校园卡将掉，拍背后卡掉落、弯腰捡卡引发误解。它没有照题目字面让主角拍到熟人，但用户认可这种自然误解也能成为笑话。原稿独立审稿幽默 3/5、文化/口语/结构/真实感各 4/5，`accepted=false`；一次整篇改写的幽默分降到 2/5，系统保留原稿。用户随后给原稿幽默 **4/5**、文化 **4/5**、口语 **4/5**、结构 **5/5**、生活真实感 **4/5**，喜欢前半段动作和想象帮忙后成为朋友的内心戏，认为结尾突然加入室友回复很怪，更适合由讲述者自己在原事件中收束。评分表 `artifacts/wrongperson_v15_human_rating.csv` 与完整轨迹 `artifacts/quality_loop_wrongperson_v15.json` 保存在本地忽略目录，不提交仓库。这是一名评分者的一篇稿，不能宣称总体生成质量达标。

用户进一步指出：符合人物性格与现实逻辑的内心预演是有力铺垫，预想和现实的偏差本来就是笑点。另一模型评价还指出旧稿把普通过渡当包袱、解释冲突过多、情节为回调服务、结尾总结感重。v16 据此移除固定的铺垫包袱组数与双回调硬门槛，独立审稿改为先看整件事是否自然好讲，事实审稿仍核查人物、场地、物品和时间连续性。创作可从一个好笑短情境扩写成故事，也可从一段经历提炼笑点；不对路线或偶然次数设配额。v16 的代码和离线测试已修改，**还没有新人工评分或可靠的效果对照**。

v16 对“认错人拍背”做了一次有上限的真实调用：跳过情境预搜索，只生成一稿并由独立审稿与事实审稿检查，完整轨迹在本任务工作区的 `outputs/quality_loop_library_v16.json`。CFunSet 模式选中一条训练参考；初稿 548 汉字、2 组结构标签、2 次回调，AutoGen 自评均分 8.17/10，独立审稿幽默/文化/口语/结构/真实感均 4/5，事实真实感 4/5，`accepted=true`。故事是误认同款卫衣后拍背，陌生人回头，主角临时解释为拍灰，真室友随后从身后回应。自动审稿未列阻断问题，但人工通读仍觉得“肩上恰有灰”方便了补救、结尾“以后拍错就说有灰”有总结感；这两点留待人评。由于 v15 与 v16 的生成及审稿协议均已变化，**不能**把两轮自动幽默 3→4 当作同口径提升；目前仍无 v16 人工分数。

v17 对**同一篇** V16A 用更明确区分故事合理性和笑点强度的审稿提示重新评估（工作区 `outputs/v16a_reaudit_v17.json`）：独立幽默 3/5，文化/口语/结构/真实感各 4/5，事实真实感 4/5，`accepted=false`；评语识别到“拍灰”便利巧合及结尾重复回调。外部模型对 V16A 的 6.5/10 及具体批评来自用户转述，不等于用户本人盲评分，也不能用模型重审分数证明真实观众更赞同。自动修稿连续返回原稿或仅移除标签，尚未生成有说服力的 V16B；现已把整篇评语传给修稿器，并拒绝归一化文本相似度 >0.985 的表面修改。下一步应在人评下测试真正改变人物动作/对白的局部改写，不因自动分数下降就机械追分。

## v17–v20：短稿与错误接受案例

同题“宿舍洗衣房等洗衣机”先跳过情境预筛选生成约 666 汉字长稿（`outputs/quality_loop_laundry_v17.json`）：AutoGen 自评均分 8.53/10，独立幽默仅 3/5，返工只返回表面改动，`accepted=false`。同题启用预筛选后选中“用盆排队”情境，约 712 汉字稿被旧独立审稿给幽默 4/5、`accepted=true`（`outputs/quality_loop_laundry_premise_v17.json`），但人工核查发现：原洗衣者未取衣，新人衣服却已开始在同一台机器内转；主角没洗过的衣服突然成为湿衣服。**这是自动假阳性，不可作为高质量样稿。**v18 事实审稿重审抓出“湿衣服”，却仍把缺少取出上一锅视为非阻断；随后增加了定向状态诊断，原稿会被拦截。新审稿和程序规则不能消除其他题材里的所有类似错误。

按用户建议将 1 分钟作为上限，生成三篇不同短稿：等洗衣机（`outputs/quality_loop_laundry_short_v18.json`，211 汉字，CFunSet 选中 2 条参考）、扫错洗衣机二维码（`outputs/quality_loop_wrong_washer_v18.json`，161 汉字，0 条参考）、互相提醒书包拉链（`outputs/quality_loop_backpack_short_v19.json`，184 汉字，0 条参考）。三稿的独立幽默均 **3/5**、`accepted=false`，但分别体现了“嘴上说刚来、手里攥热洗衣液”“空桶在转、衣服没动”“提醒别人后发现自己也没拉”的具体落差。前两篇 AutoGen 自评仍在 7.5–8.0/10 左右，显示自评偏宽。另手写 60 汉字“衣服和钱分开洗”局部稿（`outputs/washer_micro_v19.txt`）独立幽默也是 3/5；短不自动等于好笑。外部模型将“认错人拍背”改成同款黑羽绒服、拍灰、真室友在旁边的近似情节时，已提前停止调用，没有宣称新稿。

本地 `outputs/openmic_short_samples_rating.csv` 收录上述三篇完整短稿和空白五维评分，已校验 Windows Excel 适用的 UTF-8 BOM `EF BB BF`、严格 UTF-8 解码、3 行中文。用户后来在对话中给出主观编辑综合分：S1 5.8/10、S2 6.8/10、S3 4.5/10，建议重点打磨 S2、保留 S1、压缩或淘汰 S3；这不是观众测试，也不是补填原表五维 1–5 分。局部实验与原始 CFunSet 数据均不提交小组 PR。

## v21–v27：第二拍、提示长度与角色分工（开发试验）

同一 S2 洗衣房核心分别试掩饰、连续错误操作、他人反应，三稿均不推荐；其中再次扫已付错的机器被独立模型评为幽默 4/5，但人物为什么相信这能启动另一台并无依据。随后 baseline 和 CFunSet 抽象机制条件各生成 5 张第二拍卡片，独立模型均未推荐；这两组只有一次调用，不能推断 CFunSet 一般无效。结果暴露了强制升级会诱发未交代的设备操作，以及审稿模型可能把它判为好笑。

同一扶门情境先后用 v20 和压短的 v26 提示跑完整流程，独立幽默均 3/5、事实真实感均 5/5。v20 的内部质检误把历史稿件当成当前重复内容，触发两轮返工，共 11 条 Agent 消息；关闭质量闭环中的内部返工后，v26 为 5 条消息。它还出现一个多余 `[PUNCHLINE]`，因此原始协议未通过。节省调用不等于幽默提高。

对 v26 与 v27 候选编剧提示做两题同题对照，每题每条件仅一篇，生成模型相同为 `deepseek-flash`，固定相同上游简报；“洗衣房扫错机”无参考，“接触不良充电线”两条件均提供同一条 CFunSet 训练参考（ID 前缀 `6109f367815e`）。匿名 `deepseek-v4-pro` 审稿两次都偏好新提示，旧/新幽默分别 3/4 和 3/4。人工检查发现旧洗衣稿衣服未启动却已泡水，而新充电稿把五分钟电量未变直接解释成完全没充，依据不足。故这些分数只支持继续试验，不证明真实笑感提升，也不能单独归因为 CFunSet。

v27 完整五 Agent 充电题复测选中 1 条 CFunSet 参考，输出一轮 5 条 Agent 消息，AutoGen 均分 8.17/10；独立幽默 3/5、文化/口语/真实感 4/5、结构 3/5，事实真实感 4/5，`accepted=false`。它仍倾向沿用导演“拆弹”比喻，结尾只是无奈姿势，未达到可靠强笑点。当前结果是流程更少重复、提示分工更清楚，生成质量仍待人评。原始实验保存在本任务工作区 `outputs/prompt_ablation_v27.json`、`outputs/charger_quality_v27.json` 等，未提交仓库。

## v28：人工分级笑话语料训练与额外正例

下载并实际训练了 Chinese_Humor_MultiLabeled 的3,365条人工标注中文笑话，监督目标是1–5级幽默度与8类手法。训练／验证／测试为2,308／329／728。训练的是冻结BGE的回归／分类输出层及字符基线，未微调DeepSeek。字符基线等级相关性Spearman 0.2667、MAE 0.7864；语义输出层相关性0.2201、MAE 0.7982；均弱，未接入稿件通过门槛。原论文也指出单标注者幽默等级与读者反馈的关联较弱。

新增默认关闭的 `--humor-memory`：仅从人工高分训练记录检索，经一次编辑筛选后，给导演和编剧补充可借鉴的预期变化；记录原来源，不冒充CFunSet样例。三题各一对的编剧阶段匿名模型评价偏好新法2题、旧法1题；新健身房稿把储物柜认成器械，显示正例迁移也可能扩大不合理误认，不能声称质量提升。完整五Agent图书馆集成一轮5条消息，CFunSet/额外正例各2条，独立幽默仍3/5，`accepted=false`。方法、数据哈希、留出指标、精确重合检查及局限见 [HUMOR_LEARNING.md](HUMOR_LEARNING.md)。
